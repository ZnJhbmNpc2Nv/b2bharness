# Инструкция по полному тестированию B2B-harness через UI

Эта инструкция описывает пошаговый процесс сквозного (E2E) тестирования пайплайна агентной разработки в B2B-harness, включая проверку артефактов и работу с интерфейсом.

---

## 1. Подготовка и Запуск окружения

1. **Запуск Backend (FastAPI):**
   ```bash
   uvicorn src.api.main:app --reload --port 8000
   ```
2. **Запуск Frontend (React + Vite):**
   ```bash
   cd frontend
   npm run dev
   ```
3. Откройте в браузере адрес, указанный в терминале Vite (обычно `http://localhost:5173`).

---

## 2. Пошаговый сценарий тестирования на UI

### Шаг 1: Авторизация / Ввод ключа
- В верхней панели интерфейса введите любой тестовый ключ (например, `test-key`) в поле **API Key** и нажмите **Save Key**.
- После сохранения интерфейс разблокируется, появится кнопка **Clear Token** и поле ввода намерения (`Describe your intent...`).

### Шаг 2: Шаг PRE-SDD & SDD-INTENT (Формализация намерения)
- В текстовое поле ввода намерения введите описание задачи, например: 
  `"Создать микросервис аутентификации пользователей через OAuth2 с валидацией токенов"`
- Нажмите кнопку **Refine Intent**.
- Бэкенд через LLM-клиент сгенерирует нормализованный черновик намерения.
- В нижней части экрана появится блок **Refined Intent** с текстом и кнопкой **Approve & Advance**.

### Шаг 3: Проверка и скачивание промежуточных артефактов
- На экране отобразится блок **Review Artifact**, подтягивающий текущий артефакт сессии (`discovery.md` или `intent.md`).
- **Как скачать артефакты**: Вы можете напрямую открыть или скачать файлы из папки проекта:
  - `data/staging/session_001/discovery.md` (Результат реверс-инжиниринга / анализа)
  - `projects/web_ui_dashboard/intent.md` (Нормализованное намерение)
  - `projects/web_ui_dashboard/spec.md` (Спецификация требований)
  - `projects/web_ui_dashboard/plan.md` (План разработки)

### Шаг 4: Продвижение по пайплайну (Advance Stage)
- Нажмите кнопку **Approve & Advance**.
- Система проверит статус подтверждения экспертом (`approval.json`), переведет пайплайн на следующий этап (например, в состояние `INTENT` → `SPEC` → `PLAN`) и обновит статус на главной панели.
- Граф пайплайна (`PipelineGraph`) визуально подсветит текущую активную вершину.

---

## 3. Критерии успешного итога (Definition of Done)

Тест считается успешным, если:
1. **Пайплайн проходит все ключевые статусы** от PRE-SDD до SDD-DEV без критических ошибок на бэкенде.
2. **Артефакты формируются и сохраняются** в файловой системе (`data/staging/` и `projects/`), содержат валидные структурированные данные.
3. **UI корректно отображает текущий этап**, подгружает артефакты в блок ревью без ошибок 404 и позволяет согласовывать переходы (`Approve & Advance`).
