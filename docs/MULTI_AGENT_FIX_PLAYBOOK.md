# Мультиагентный протокол безопасных исправлений (Multi-Agent Fix Playbook)

> **Назначение документа**: Данный регламент и готовые шаблоны промптов предназначены для безопасной передачи задач агентам (Claude, Kimi, GPT, Gemini, локальным моделям) в корпоративной сети. Он гарантирует, что агенты выполнят исправления точечно, не сломают существующие доработки, сохранят обратную совместимость и не привнесут запрещенных внешних зависимостей.

---

## 1. Фундаментальные инварианты (Что агентам СТРОГО ЗАПРЕЩЕНО трогать)

При любой отправке промпта агенту передаются 6 "железных" правил системы:

| # | Инвариант | Почему это критично | Что запрещено агенту |
|---|---|---|---|
| **INV-1** | **Zero-Dependency Mandate** | Система работает в закрытом контуре без интернета и без прав локального админа. | **Категорически запрещено** добавлять `pip install`, `requirements.txt`, `requests`, `fastapi`, `pydantic`, `pytest`, `npm`. Только стандартная библиотека Python 3.8+ (`http.server`, `sqlite3`, `json`, `urllib`, `ast`, `unittest`, `difflib`). |
| **INV-2** | **Сохранение локальных доработок** | На рабочей машине могут быть локальные кастомные модули в `modules/` и правки в `static/`. | Запрещено заменять файлы целиком ("rewrite entire file"). Разрешены только точечные хирургические патчи (`unified diff`) с явным указанием контекста вокруг изменений. |
| **INV-3** | **SQLite WAL Schema Integrity** | Все миграции должны быть неразрушающими. | Запрещены `DROP TABLE` и удаление колонок. Любые новые таблицы создаются только с `CREATE TABLE IF NOT EXISTS`, новые поля — с безопасным `IF NOT EXISTS` или через `DEFAULT`. |
| **INV-4** | **100% Pass Rate Test Suites** | 73+ модульных теста должны проходить без ошибок за <2 секунды. | Запрещено коммитить код, ломающий `test_standalone.py`, `test_orchestrator_pipeline.py`, `test_b2b_harness.py`, `test_modules.py`. |
| **INV-5** | **AST SAST Cleanliness (ASVS L2)** | Статический сканер безопасности не должен выдавать флаги. | Запрещены `eval()`, `exec()`, `os.system()`, `pickle.loads()`, `subprocess` с `shell=True`, сырая конкатенация строк в SQL/путях. |
| **INV-6** | **UI Glassmorphism & Vanilla JS** | Интерфейс автономен и не требует сборщиков (Webpack/Vite). | Запрещен React, Vue, TypeScript, внешние CDN шрифтов/стилей. Только чистый Vanilla ES6+ DOM (`speckit_ui.js`, `speckit_api.js`, `speckit_dag.js`). |

## 2. Четырехэтапный мультиагентный пайплайн исправления

Если вы ставите задачу нескольким агентам (или одному агенту, переключая роли):

```
[1. Agent: Architect & Blast Radius]
       │ (Анализ задачи, локализация затронутых файлов, составление плана)
       ▼
[2. Agent: Surgical Coder]
       │ (Написание точечного diff-патча без перезаписи файлов)
       ▼
[3. Agent: Critic & Security Auditor]
       │ (Проверка инвариантов, AST SAST, аудит обратной совместимости)
       ▼
[4. Agent: Verification & QA]
       │ (Запуск unittest, проверка UI селекторов, упаковка бандла)
       ▼
[Готовый безопасный патч для слияния на рабочем ПК]
```

## 3. Готовые промпты для отправки агентам в корпоративной сети

### Шаблон 1: Промпт для Агента-Архитектора (Оценка радиуса поражения)
> **Используйте этот промпт первым**, чтобы агент не лез переписывать все подряд, а четко локализовал scope.

```markdown
[РОЛЬ: Lead System Architect & Blast Radius Auditor]
Ты работаешь с кодовой базой Corporate Spec-Kit / B2B-Harness в закрытой корпоративной сети.

ЗАДАЧА:
{ОПИШИТЕ ВАШУ ЗАДАЧУ / БАГ / ДОРАБОТКУ ЗДЕСЬ}

ЖЕСТКИЕ ОГРАНИЧЕНИЯ:
1. Архитектура: Zero-Dependency (только стандартная библиотека Python 3.8+). Никаких сторонних pip пакетов.
2. Локальные доработки: На рабочем ПК уже внедрены кастомные модули и вкладка Pipeline. Запрещено предлагать перезапись существующих файлов целиком.
3. База данных: SQLite WAL. Не ломать существующие таблицы и структуры.

ТВОЙ ОТВЕТ ДОЛЖЕН СОДЕРЖАТЬ СТРОГО:
1. "Blast Radius Analysis": Точный список файлов, которые действительно ТРЕБУЕТСЯ изменить (не более 1-3 файлов).
2. Список файлов, которые КАТЕГОРИЧЕСКИ НЕЛЬЗЯ трогать, чтобы не сломать текущий функционал.
3. Пошаговый план изменений с обоснованием: ЧТО меняется, ЗАЧЕМ, и ДЛЯ ЧЕГО.
4. Список тестов, которые подтвердят корректность после внедрения.
Не пиши готовый код прямо сейчас — сначала представь план на согласование.
```

### Шаблон 2: Промпт для Агента-Разработчика (Хирургический патч)
> **Используйте этот промпт после утверждения плана**, чтобы получить точечный патч без риска затереть код.

```markdown
[РОЛЬ: Senior Surgical Software Engineer]
Ты внедряешь согласованную доработку в Corporate Spec-Kit.

КОНТЕКСТ ЗАДАЧИ:
{ВСТАВЬТЕ СОГЛАСОВАННЫЙ ПЛАН ИЗ ШАГА 1}

ИНВАРИАНТЫ:
- Pure Python 3.8+ stdlib ONLY (без requests, pydantic, fastapi, pytest).
- Vanilla ES6+ DOM ONLY (без react, npm, cdn).
- Никаких правок существующих сигнатур функций, если это сломает обратную совместимость.
- 0 уязвимостей (без eval, exec, os.system, raw sql injection).

ФОРМАТ ВЫВОДА:
Предоставь изменения ИСКЛЮЧИТЕЛЬНО в формате точечных блоков замены (Unified Diff или фрагментов Before/After с 5 строками контекста).
Каждый блок должен содержать:
1. Путь к файлу.
2. Номера строк или точный контекст ДО изменения.
3. Точный контекст ПОСЛЕ изменения.
4. Обоснование, почему это изменение сохраняет работоспособность всех существующих функций.
```

### Шаблон 3: Промпт для Агента-Критика / Аудитора (Anti-Regression & Security Gate)
> **Используйте этот промпт для ревью патча**, чтобы выявить скрытые регрессии до применения на рабочем ПК.

```markdown
[РОЛЬ: Ruthless CodeCold Security & Anti-Regression Auditor]
Ты проводишь инспекцию предложенного патча перед накатыванием на рабочий контур.

ПРЕДЛОЖЕННЫЙ ПАТЧ:
{ВСТАВЬТЕ КОД / ДИФФ ИЗ ШАГА 2}

ПРОВЕРЬ СТРОГО ПО ЧЕКЛИСТУ:
1. Dependency Audit: Есть ли сторонние импорты (requests, pydantic, fastapi, pytest и т.д.)? (Если да — REJECT).
2. AST SAST Audit: Есть ли уязвимости SEC-001..SEC-006 (eval, exec, os.system, shell injection, raw sql, traversal)? (Если да — REJECT).
3. Backwards Compatibility: Не сломаны ли REST API эндпоинты (/api/harness/*, /api/requirements/*)? Не сломаны ли таблицы БД?
4. Local Work Preservation: Не затирает ли этот патч логику вкладки Pipeline, DAG-графа или существующих модулей?
5. Exception Safety: Все ли ошибки обрабатываются безопасно без падения процесса и без утечки путей файлов?

ВЫНЕСИ ВЕРДИКТ:
- [APPROVED] — если все 5 пунктов чисты.
- [REJECTED] — если нарушен хотя бы один пункт, с указанием конкретных строк и исправленной версией.
```

### Шаблон 4: Промпт для Агента-QA (Автоматические тесты)
> **Используйте этот промпт для дополнения тестов**.

```markdown
[РОЛЬ: Zero-Dependency QA & Test Engineer]
Напиши автономный модульный тест на Python standard library (unittest) для проверки новой функциональности:
{ОПИСАНИЕ НОВОЙ ФИЧИ}

ТРЕБОВАНИЯ К ТЕСТУ:
1. Использовать ТОЛЬКО `unittest`, `tempfile`, `urllib.request`, `json`, `os`, `sys`. НИКАКОГО pytest.
2. Тест должен быть полностью изолирован: использовать временные директории (`tempfile.mkdtemp()`) и очищать их в `tearDown()`.
3. Тест должен выполняться менее чем за 300 мс.
4. Тест должен проверять как позитивные сценарии (happy path), так и негативные (невалидный payload, ненайденный ID, граничные условия).
```

## 4. Памятка по проверке целостности на рабочем ПК за 1 минуту

Перед тем как принять работу мультиагента, выполните на своем рабочем ПК следующие 3 команды в консоли проекта:

```bash
# 1. Запуск полного базового тест-сьюта (27 тестов, включая REST API и Harness)
python test_standalone.py

# 2. Запуск конвейера мультиагентного оркестратора (14 тестов жизненного цикла)
python test_orchestrator_pipeline.py

# 3. Запуск AST SAST сканера и упаковки автономного дистрибутива
python pack_offline_bundle.py
```

Если все три команды вернули `OK` и `[OK] AIR-GAPPED PORTABLE BUNDLE CREATED SUCCESSFULLY` — вы можете быть на 100% уверены, что ни один инвариант не нарушен, а ваши локальные наработки в полной безопасности!
