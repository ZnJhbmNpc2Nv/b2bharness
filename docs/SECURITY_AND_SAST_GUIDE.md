# Руководство по Безопасности, Санитизации и AST SAST

## 1. Pre-Flight Secret Scrubber (Очистка Секретов)

Перед анализом и исполнением чужого vibe-кода модуль `SecretScrubber` автоматически инспектирует файлы и удаляет чувствительные данные:

- **Токены LLM и API**:
  - OpenAI / Anthropic: `sk-[a-zA-Z0-9]{20,}`, `sk-ant-[a-zA-Z0-9_-]{20,}`
  - HuggingFace: `hf_[a-zA-Z0-9]{20,}`
- **Облачные ключи**:
  - AWS Access Key ID: `AKIA[0-9A-Z]{16}`
  - AWS Secret Access Key: строковые присвоения 40-символьных base64 строк.
- **Токены VCS**:
  - GitHub Personal Access Token: `ghp_[a-zA-Z0-9]{36}`, `github_pat_...`
- **Приватные ключи**:
  - Заголовки `-----BEGIN (RSA|EC|DSA|OPENSSH|PGP) PRIVATE KEY-----`
- **Строки подключения к БД**:
  - `postgres://user:pass@host/db`, `mysql://...`

Все обнаруженные секреты заменяются на маркеры `***REDACTED_SECRET[TYPE]***`.

## 2. Изолированная Песочница (Isolated Sandbox)

Исполнение непроверенного кода осуществляется через контроллер `IsolatedSandboxRunner`:
- **Очистка окружения**: Из `os.environ` удаляются все переменные, содержащие `KEY`, `TOKEN`, `SECRET`, `PASSWORD`, `AUTH`.
- **Изоляция сети**: Устанавливаются фиктивные прокси `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY=socks5://127.0.0.1:0` и инжектируется заглушка, блокирующая создание сокетов с ошибкой `PermissionError`.
- **Лимиты ресурсов**:
  - Жесткий таймаут выполнения (по умолчанию 30–60 секунд с принудительным `SIGKILL`/`terminate`).
  - Ограничение объема вывода stdout/stderr (максимум 100 КБ) для защиты от переполнения оперативной памяти.

## 3. Статический AST SAST Анализ

Модуль `AstSastScanner` реализует проверку безопасности на базе встроенного модуля `ast.NodeVisitor` без внешних зависимостей:

| Правило | Категория | Описание уязвимости |
|---|---|---|
| **SEC-001** | SQL Injection | Использование f-строк, конкатенации `%` или `.format()` внутри методов `.execute()` или `.raw()`. |
| **SEC-002** | Command Injection | Вызовы `subprocess.*` с аргументом `shell=True`, либо прямые вызовы `os.system()` и `os.popen()`. |
| **SEC-003** | Insecure Deserialization | Небезопасная десериализация через `pickle.loads()` / `pickle.load()` или `yaml.load()` без SafeLoader. |
| **SEC-004** | Unsafe Dynamic Code | Прямое исполнение произвольного кода через встроенные функции `eval()` или `exec()`. |
| **SEC-005** | Path Traversal | Прямое открытие файлов `open()` с конкатенацией непроверенных путей без `os.path.abspath`. |
| **SEC-006** | Weak Cryptography | Использование алгоритмов MD5/SHA-1 без указания флага `usedforsecurity=False`. |

## 4. SBOM и Криптографическая Печать Модуля

- **CycloneDX 1.5 JSON SBOM**: Генератор `SbomGenerator` анализирует внешние импорты и формирует спецификацию состава программного обеспечения.
- **Криптографическая печать (`ModuleSealer`)**: Вычисляет SHA-256 контрольные суммы всех файлов дистрибутива и формирует файл манифеста `seal.json`, гарантируя защиту от несанкционированной подмены.
